### PRIN-001 도메인 파일 구성: 10-page(PAGE)·20-bot(BOT) 2개

- 상태: 확정
- 날짜: 2026-11-16
- 관련 결정: 없음
- 추천 여부: 추천 채택

#### 맥락
운영 18주차, 소스 약 1천 줄의 봇에 결정 중심 개발을 도입한다. 앞으로 쌓일 결정은 글개 홈페이지(화면·데이터·공개 정책)와 봇 동작(명령·cron·공지) 두 축이다. (출처: Q-001)

#### 선택지
- A. 00-principles·05-vision + 10-page(PAGE)·20-bot(BOT) 2개
- B. 표준 구성(architecture/data-model/interface/security 등)
- C. 단일 파일(10-decisions)

#### 결정
A. `10-page.md`(접두어 `PAGE`: 홈페이지 화면·보여줄 데이터·공개 정책), `20-bot.md`(접두어 `BOT`: 명령·cron·운영 동작)를 둔다.

#### 이유
이 규모에서 결정이 실제로 발생하는 축과 파일이 1:1로 맞고, 빈 파일이 없다.

#### 기각된 선택지와 이유
- B: 범용적이지만 이 규모에선 빈 파일이 많아진다.
- C: 가장 작지만 도메인 구분이 없어 추적이 불편해진다.

#### 재검토 조건
한 파일의 결정이 100건을 넘으면 하위 파일로 나눈다.

### PRIN-002 문서 언어: 한국어 본문 + 영어 ID·식별자

- 상태: 확정
- 날짜: 2026-11-16
- 관련 결정: PRIN-001
- 추천 여부: 추천 채택

#### 맥락
기존 문서(README, docs/specs)와 지금까지의 커밋 메시지가 전부 한국어다. (출처: Q-002)

#### 선택지
- A. 한국어 본문 + 영어 ID·파일명·코드 식별자
- B. 전부 영어

#### 결정
A. 결정·질문·작업·세션 요약의 본문은 한국어로 쓰고, ID·파일명·코드 식별자는 영어로 쓴다.

#### 이유
기존 문서와 일관되고, 생각이 끊기지 않으며, 경로·식별자는 영어가 도구에서 안전하다.

#### 기각된 선택지와 이유
- B: 공개 저장소의 외부 독자에겐 낫지만 독자가 사실상 스터디 멤버뿐이고 기존 문서와 이중 언어가 된다.

#### 재검토 조건
외부 기여자가 생기면 다시 본다.

### PRIN-003 코드 커밋 규칙: 접두어 없는 영어 명령문으로 전환

- 상태: 확정
- 날짜: 2026-11-16
- 관련 결정: PRIN-002
- 추천 여부: 다른 선택 (추천: 기존 한국어 컨벤션 유지)

#### 맥락
이 저장소의 기존 코드 커밋 96건은 한국어 `feat:`/`fix:` 컨벤션이고, 결정 중심 개발 표준은 접두어 없는 영어 명령문이다. 둘이 충돌해 하나를 골라야 한다. (출처: Q-003)

#### 선택지
- A. 기존 한국어 컨벤션 유지 + 본문에 Decisions:/Tasks: 추가
- B. DDD 표준으로 전환: 접두어 없는 영어 명령문(Add …, Fix …)

#### 결정
B. 지금부터 코드 커밋은 접두어 없이 영어 명령형 동사로 시작하고(`Add …`, `Fix …`), 본문에 `Decisions: <ID>`와 `Tasks: <T-ID>`를 적는다. 문서 커밋은 `decision:`/`question:`/`task:`/`docs:`/`meta:` 접두어를 쓴다. 기존 로그는 소급 수정하지 않는다.

#### 이유
방식 표준을 그대로 따라 커밋 형식에서 결정 추적(Decisions: 줄)이 끊기지 않게 한다.

#### 기각된 선택지와 이유
- A: 18주치 로그와의 일관성은 있지만, 사용자가 방식 표준 쪽을 택했다.

#### 재검토 조건
로그 스타일 혼재가 실제로 불편해지면 다시 본다.
