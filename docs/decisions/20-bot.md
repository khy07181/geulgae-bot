### BOT-001 1월 1일 결산 링크 공지: 두지 않는다

- 상태: 확정
- 날짜: 2026-11-16
- 관련 결정: VIS-001, PAGE-001
- 추천 여부: 다른 선택 (추천: 포함)

#### 맥락
결산 내용은 페이지에서 즉석 계산되므로, 남는 문제는 1월 1일에 봇이 채널로 결산 페이지 링크 한 줄을 공지할지뿐이었다. (출처: Q-008)

#### 선택지
- A. 포함: 1월 1일 10:00 KST cron으로 링크 한 줄 공지
- B. 제외: 페이지만 두고 공지는 없음

#### 결정
B. 결산 공지 cron을 추가하지 않는다. 봇 cron은 기존 3개(정산·안전망·리마인더)를 유지하고, 홈페이지는 GET 요청과 `/닉네임` 커맨드만으로 동작한다.

#### 이유
비밀 경로(PAGE-001)라 링크는 멤버끼리 공유하면 되고, 사용자가 봇 공지를 늘리지 않는 쪽을 택했다.

#### 기각된 선택지와 이유
- A: 다 같이 보는 푸시 순간을 만들 수 있지만, cron과 공지 문구가 늘어난다.

#### 재검토 조건
결산 시즌에 아무도 페이지를 열지 않으면 공지 추가를 다시 논의한다.

### BOT-002 /닉네임 커맨드: 본인만 변경

- 상태: 확정
- 날짜: 2026-11-17
- 관련 결정: PAGE-002
- 추천 여부: 추천 채택

#### 맥락
기존 봇 철학은 "모든 명령은 누구나 + 공개 기록으로 견제"(관리자 없음)지만, 닉네임은 개인 정체성이다. (출처: Q-012)

#### 선택지
- A. 본인만: `/닉네임 <이름>`은 실행자 자신의 표기만 바꾼다
- B. 대상 지정 허용

#### 결정
A. `/닉네임`은 실행자 본인의 페이지 표기 이름만 등록·변경한다. 커맨드 옵션·응답 공개 방식·익명 라벨 형식 등 구현 세부에서 임시로 정하는 값은 구현 보고 때 따로 표시해 확정받는다.

#### 이유
표기 이름을 본인이 통제한다는 PAGE-002의 이유와 일관되고 구조가 단순하다.

#### 기각된 선택지와 이유
- B: 기존 철학과는 일관되지만, 이름은 장부가 아니라 정체성이라 남이 정할 일이 아니다.

#### 재검토 조건
닉네임 미등록자가 오래 남아 서재가 익명 라벨투성이가 되면 다시 본다.

### BOT-003 /닉네임 세부: 20자 제한, 실행 자리 공개 응답

- 상태: 확정
- 날짜: 2026-11-17
- 관련 결정: BOT-002, PAGE-002
- 추천 여부: 추천 채택

#### 맥락
T-001 구현 중 임시로 정한 값 2개를 보고했고, 사용자가 그대로 확정했다. (출처: Q-014)

#### 선택지
- A. 그대로: 길이 제한 20자(`NICKNAME_MAX_LENGTH`), 실행한 자리에 공개 응답(멘션 알림 끔)
- B. 값 변경

#### 결정
A. 닉네임은 공백 제거 후 1~20자. 응답은 주차와 무관한 전체 설정이므로 벌금 명령과 같은 정책으로 실행한 자리에 공개하고, `allowed_mentions`는 끈다. 미등록자의 익명 라벨 형식은 서재 렌더(T-002) 구현 보고에서 따로 확정한다.

#### 이유
공개 응답은 기존 봇의 "공개 기록으로 견제" 정책과 일관되고, 20자는 화면 깨짐 없이 충분하다.

#### 기각된 선택지와 이유
- B: 바꿀 이유가 제시되지 않았다.

#### 재검토 조건
닉네임이 서재 레이아웃을 깨뜨리는 사례가 나오면 제한을 다시 본다.
